# Архитектура «Комбайн» (Kombaine)

## 1. Обзор

Автономная система генерации, отбора и сопровождения торговых стратегий для
фьючерсных инструментов (RU-рынок). Система сама:

- придумывает новые стратегии (включая эволюционный и нейросетевой поиск),
- тестирует их на исторических данных и на невидимых (holdout) периодах,
- отбирает устойчивый портфель стратегий,
- исполняет сигналы на **бумажном счёте** (реальные свечи, виртуальные позиции),
- ведёт аналитику и возвращает её обратно в генератор — замкнутый контур.

Движок исполнения работает в режиме paper-first; переход в live — только после
квалификации и явного разрешения владельца.

## 2. Ключевая идея

Вместо одной «вечной» стратегии система поддерживает **портфель стратегий** с
автоматическим жизненным циклом:

- генератор предлагает кандидатов → проверка → реестр → ожидание → активный портфель;
- убыточные или «замолчавшие» стратегии вытесняются более сильными кандидатами;
- риск-менеджер ограничивает бюджет на залоги (ГО), просадки и дельту портфеля;
- аналитика каждого дня даёт генератору обратную связь (какие паттерны/режимы прибыльны).

## 4. Компоненты

### 4.1 Реестр стратегий (canonical registry)

Единый источник истины о всех сгенерированных стратегиях. Хранит историю генерации,
текущий статус, качественные оценки и историю переходов между состояниями:

`candidate → waitlist → watchlist → signal pool → active / rejected / rotated_out`

### 4.2 Генератор стратегий

Ночной контур создаёт кандидатов из нескольких источников:

- параметрический перебор готовых семейств стратегий;
- генетический (эволюционный) поиск новых комбинаций из DSL-атомов;
- нейросетевая модель как генератор сигналов;
- подсказки аналитики (прибыльные паттерны, текущий режим рынка, перекос портфеля).

Каждый кандидат проходит обязательный retest на свежих данных до попадания в реестр.

### 4.3 Риск-менеджер

Детерминированные правила (без LLM):

- **вытеснение** слот-стратегии: Profit Factor < 0.9 на окне 20 сделок, три стопа
  подряд, просадка слота > 15% депозита, отсутствие сигналов > 5 дней;
- **замена**: вытесненный слот занимает кандидат, прошедший retest и превосходящий
  худший активный слот по portfolio-aware оценке;
- **портфель**: общий бюджет ГО ≤ 65% депозита; дельта-контроль (net exposure в
  полосе ±30%, при перекосе генератору уходит запрос на шорт/нейтральные стратегии);
  суммарная просадка > 25% → все слоты в paper-only.

### 4.4 Детектор режима рынка

Периодически оценивает режим по всему юниверсу тикеров:

- тренд/флэт через ADX(14) и соотношение EMA20/EMA60;
- волатильность через ATR-перцентиль.

Режим влияет на направление генерации (bias) и принудительный retest активных
слотов при смене рынка (гистерезис — без мгновенных замен).

### 4.5 Аналитика и обратная связь

SQLite-хранилище сделок и метрик: P&L, Profit Factor, Win%, Sharpe, просадка,
частота сделок. Плюс аналитика входов (час, режим, расстояние до VWAP/EMA) — что
коррелирует с прибылью. Агрегированные выводы возвращаются в генератор.

### 4.6 Движок исполнения

Paper-режим: живой поток свечей (read-only), виртуальные позиции, запись сделок
в аналитику. Live — отдельный тумблер, доступный только после квалификации:
лимитные ордера, проверка ГО до заявки, kill-switch по просадке.

## 5. Конвейер исследования стратегий

```
данные → генерация/бэктест → ML-метафильтр → отбор пула → отбор портфеля → forward-test
```

- **Бэктест**: честное исполнение с комиссиями и проскальзыванием; walk-forward и
  holdout-периоды, невидимые для генерации.
- **ML-метафильтр**: модель (Ridge) прогнозирует P&L сделки по признакам входа;
  стратегии, умирающие под фильтром, штрафуются при отборе.
- **Отбор пула**: барьеры по марже (ГО контракта ≤ доли капитала), просадке, P&L,
  Sharpe, PF, частоте сделок; ограничение на тикер и размер пула.
- **Отбор портфеля**: greedy-добавление стратегий, улучшающих гладкость суммарной
  кривой капитала (calmar), с соблюдением бюджета ГО.
- **Forward-test**: финальная проверка на данных, которые не видел ни один движок.

## 6. Слой движков поиска (engines/)

Каркас конвейера не меняется — наращивается набор «мозгов», производящих кандидатов:

- **E1 zoo / autopilot** — готовые семейства × сетка параметров;
- **E2 genetic** — эволюционный поиск новых стратегий из атомов (rsi, adx, macd,
  cci, bb, vol, trend…) с векторизованным симулятором и fitness на гладкость;
- **E3 momentum** — дневные автокорреляционные паттерны;
- **E4 neural** — ансамбль MLP-моделей на каждый тикер (38 признаков: импульсы,
  волатильность, объёмы, кросс-рынок, волатильный режим, календарь), разметка по
  честной экономике сделки, практики ML: purge-границы, random search, калибровка,
  grad-clip, cosine LR;
- **E5+** — новый движок = новый файл; воронка отбора не меняется.

Единое правило: каждый прогон сравнивается с предыдущим лучшим на честном
(невидимом) окне; улучшение принимается только при подтверждённом выигрыше.

Арбитр входов — надстройка, которая может только подтверждать/ветить сделку,
видя поток всех мнений (рыночные признаки, нейросеть, метафильтр). Включается
только если на валидационном разрезе строго лучше базовой версии.

## 7. Режимы работы и безопасность

- Paper-first: любая стратегия сначала торгуется на бумаге; бэктест и живой рынок
  дают разные цифры.
- Реальные ордера — только после квалификации и явного разрешения владельца.
- Секреты (токены брокера и API) — только через переменные окружения, никогда в коде.
- Детерминированный риск-код без LLM: лимиты и kill-switch не зависят от генеративных моделей.

```

tests/   — unit + интеграционные + dry-run проверки
docs/    — архитектурные заметки и решения
```
