## 0. Исходная идея (Апостол)
Одна самая профитная стратегия (1-2 сделки/день, НЕ RI) → вокруг неё комбайн:
риск-менеджмент портфеля, доска ожидания стратегий, ежедневный генератор новых
стратегий, авто-выкидывание убыточных, аналитика с обратной связью в генератор,
режим рынка (тренд/боковик) управляет направлением генерации, дельта портфеля к нулю.

## 1. Честная сверка с реальностью (что имеем сейчас)
- Лучшая БЕЗ RI по профиту: **LKOH ft_supertrend** — PNL N ₽ (OOS), Sharpe 0.90,
  **1.56 сделок/день**, 13 сделок за 8.3 дня теста. Частота почти в цели, но выборка мала.
- На часовых барах 60 дней потолок частоты ~1.5 сделки/день. Для стабильных 1-2/день
  по каждой стратегии нужен **интрадей-слой данных** (15м/5м) — он уже используется в части контура.
- Депозит ~20 000 ₽. Реально влезает 2-3 активных слота по ГО:
  Слоты подбираются по ГО и депозиту (порядка 5–15% депозита на слот).
- RI исключён Апостолом.

### 2.1 CANONICAL REGISTRY (источник истины)
`combine/state/strategy_registry.json` — **главное** хранилище всех сгенерированных стратегий.

Registry хранит:
- полную историю генерации,
- текущий статус стратегии,
- portfolio-aware контекст,
- quality gate,
- history trail переходов,
- active_rank и placement-слоты.

**Статусы registry:**
- `registry/candidate`
- `waitlist`
- `active_watchlist`
- `active_signal_pool`
- `rejected`
- `rotated_out`
- `conflicted`
- `expired`

**Важно:** legacy-файлы `waitlist.json` и `signal_pool.json` теперь считаются
**compat views**. Они остаются для обратной совместимости старых модулей и старых
тестов, но не должны быть единственным источником истины.

### 2.2 RISK MANAGER (оркестратор, детерминированный код без LLM)
Правила выкидывания (срабатывает любое):
- R1: скользящие 20 сделок → Profit Factor < 0.9
- R2: накопленный убыток слота > 2×ATR-стопа × контракты × 3 (три стопа подряд)
- R3: просадка слота > 15% депозита
- R4: стратегия молчит > 5 дней (сигналов нет) — мёртвый вес

Правила замены: выкинутый слот → берём top candidate из canonical registry /
compat waitlist, прошедший fresh-retest, если кандидат по portfolio-aware score
лучше худшего активного слота с маржой.

Правила портфеля:
- общий бюджет ГО ≤ 65% депозита;
- дельта-контроль: net_exposure (long минус short в ГО) держать в полосе ±30%;
  генератору уходит запрос «нужна шорт/флэт стратегия» при перекосе;
- стоп всего портфеля: суммарная просадка > 25% → все слоты в paper-only, алерт Апостолу.

### 2.3 WAITLIST / SIGNAL POOL (legacy compat views)
`combine/state/waitlist.json` — legacy-вид очереди кандидатов.

`combine/state/signal_pool.json` — legacy-вид активного сигнального пула.

Эти файлы теперь производные от canonical registry и используются для:
- совместимости с существующим live-движком,
- плавной миграции,
- сохранения текущих тестов и тикера жизненного цикла.

Поведение:
- кандидат без promotion TTL=7 дней → retest на свежих данных;
- promotion в портфель только если candidate beat`-ит худший live-слот;
- max signal pool size остаётся 10 как compat-граница;
- status transitions пишутся в registry, а views экспортируются из него.

### 2.4 GENERATOR (ночной, раз в день)
Контур: cron 01:00 → Pi-пайплайн (architect→coder→tester) либо детерминированный
param-search + новые шаблоны стратегий.

Вход генератора (обратная связь из ANALYTICS):
- regime_bias: «тренд вверх даёт деньги → генерируй трендовые long»;
- gap_bias: «портфель перекошен в long → нужны шорт/нейтральные»;
- analytics_hints: какие входы/выходы/тикиры/часы дают деньги (топ факторы);
- текущие убыточные паттерны (чего избегать).

Выход: пачка кандидатов → обязательный retest на свежих данных → в REGISTRY и
legacy compat views.
Лимит ночных прогонов — ограничивается ресурсами, но registry не ограничен размером:
стратегии сохраняются в persistent registry всегда, даже если не попали в live watchlist.

### 2.5 REGIME DETECTOR
Раз в 6 часов считает по юниверсу (BR/GAZP/LKOH/SBER/Si):
- ADX(14) по дневкам: тренд/флэт по каждому тикеру;
- направление: EMA20 vs EMA60;
- волатильность: ATR% перцентиль за 60 дней.

Пишет regime_log.jsonl + текущий snapshot. Детектор даёт генератору bias,
риск-менеджеру — сигнал «рынок сменился → проверить слоты на совместимость»
(не мгновенная замена, а принудительный retest всех активных слотов на свежих 14 днях;
замена только по его итогам — гистерезис против чехарды).

### 2.6 ANALYTICS STORE
`combine/analytics.db` (SQLite):
- trades: время, слот, тикер, направление, вход/выход, PNL, причина выхода
  (TP/SL/timeout/regime/eject);
- per-strategy rolling stats: PF, Win%, Sharpe, DD, сделок/день;
- entry analytics: час входа, regime на входе, расстояние до VWAP/EMA — что коррелирует с профитом;
- generator_feedback: агрегированные hints для ночного генератора.

Ежедневный digest в Telegram (отчёт для Апостола: PNL дня, слоты, замены, regime).

### 2.7 EXECUTION ENGINE
Только **paper trading** на старте: движок гоняет стратегии по живым свечам Tinkoff
(read-only), ведёт виртуальные позиции, пишет трейды в ANALYTICS.

Live-режим — отдельный тумблер, только после: (а) 2 недель paper со статистикой,
(б) явной команды Апостола. Ордеры только через лимитки с защитой (макс контракты,
проверка ГО до заявки, kill-switch по просадке).

## 3. Порядок сборки (фазы)
- **F0. Данные** — докачать интрадей 15м по юниверсу (read-only), починить битые 15м-файлы.
- **F1. Якорь** — дождаться extended-скана (идёт, зоопарк 26→40+, без RI), выбрать
  якорную стратегию по двойному гейту: rank_score И сделок/день ≥ 1. Если ни одна не
  проходит — генератор целенаправленно ищет частотную.
- **F2. Движок исполнения** — paper trading контур (сигнальный цикл, позиции, PNL).
- **F3. Risk Manager + Registry** — слоты, бюджет ГО, правила R1-R4, замены,
  canonical registry и compat views.
- **F4. Waitlist + Generator** — ночной контур, TTL, fresh-retest, promotion.
- **F5. Regime Detector + обратная связь** — bias в генератор, retest при смене режима.
- **F6. Аналитика + дашборд** — SQLite, digest в Telegram.

## 4. Мои правки к исходной идее (почему так)
1. **Выкидывать не за 2-3 убыточных сделки** — на малых выборках шум. Окно 20 сделок
   или явный пробой лимитов (R2/R3), иначе комбайн будет молотить сам себя.
2. **Гистерезис замен** (маржа + retest) — без неё портфель будет чехардой
   каждый день, комиссии съедят всё.
3. **Дельта к нулю — цель, но не самоцель**: на 20к и 2-3 слотах полный нейтрал
   недостижим (не хватает ГО на пары). Полоса ±30% реалистична; к нулю идём по мере
   роста депозита.
4. **Paper-first обязательно**. Любая «готовая» стратегия сначала paper —
   бэктест и живой рынок дают разные цифры (проскальзывание, ликвидность).
5. **Generator не LLM-only**: детерминированный param-search надёжнее; Pi-агенты
   предлагают новые ШАБЛОНЫ стратегий из аналитики, но валидирует всё tester.
6. **Canonical registry first**: новые стратегии фиксируются в `strategy_registry.json`,
   а waitlist/signal_pool — только производные compat views.

## 5. Риски
- Мало данных для частотных стратегий → F0 решает (15м слой).
- Оверфит на 60 днях → walk-forward уже в движке, + fresh-retest при promotion.
- Сервер слабоват (RAM) → ночные прогоны по одному, лимиты, чекпоинты.
- 21к депозит → 2-3 слота максимум, диверсификация слабая; растим депозит с профита.
- Миграция state → пока есть legacy views, важно не допустить расхождения между
  canonical registry и compat-файлами.

### 9.1 Полный цикл (что реально крутится)

```
[данные] /root/prop-desk/futures_lab/artifacts/tinkoff_futures_data/
   *_365d_1h_continuous.csv по тикерам CORE_UNIVERSE (core/production_truth.py)
        │
        ▼
[генерация+бэктест] code/strategy_architect_autopilot.py
   40 стратегий из futures_lab/strategy_zoo.py (STRATEGY_NAMES),

   → reports/research_pipeline/runs/<run_id>/ (candidates.jsonl, eligible_candidates.json)
   → state/strategy_registry.json (canonical, статусы candidate→waitlist→watchlist→pool)
        │
        ▼
[ML мета-фильтр] tools/rebuild_meta_cache.py → state/meta_filter_cache.json
   Ridge(alpha=CV) предсказывает P&L каждой сделки по признакам входа
   (RSI, ATR%, тренд, вола, моменты, z-score, час; признаки с бара ДО входа).
   Обучение: первые 70% сделок каждой стратегии (хронологически), тест 30%.
   Стратегии, умирающие под фильтром (filt<=0), штрафуются при отборе.
        │
        ▼
[отбор пула] tools/rerank_signal_pool.py → state/signal_pool.json (compat view)
   Барьеры: маржа 1 контракта ≤ 50% капитала 20к; просадка ≤ 35%;
   pnl>0, Sharpe≥0.5, PF≥1.05, trades≥5; ≤2 на тикер; пул ≤10.
   quality_score учитывает meta_filter_cache.
        │
        ▼
[стабильностный портфель] tools/select_stable_pool.py → state/stable_pool.json
   Критерий Апостола: equity ДОЛЖЕН быть стабильно растущим, прибыль вторична.
   Гейты: ≥7 прибыльных месяцев из 12, calmar (pnl/maxDD) ≥ 1.5, meta_ok.
   Портфельный greedy-отбор: стратегия добавляется, только если СУММАРНАЯ
   кривая портфеля становится глаже (calmar растёт).
```

### 9.7 Риск-сайзинг и планка дохода (2026-09-05, требование Апостола)

Планка: медиана месяца портфеля НЕ НИЖЕ 1200₽ (снижена с 3000 решением Апостола
2026-09-06 после честного аудита — 3000₽/мес на 20к недостижимо без переобучения).
Портфель ниже планки — НЕ ПРИНЯТ (`accepted=false` в stable_pool.json).

Сайзинг как в реальном проп-деске (tools/select_stable_pool.py):
- риск на сделку = 2% капитала (400₽);
- реальный риск 1 контракта = медиана |убытка| сделки из 1-контрактного бэктеста;
- контракты = clamp(1..3, min(risk_cap, margin_cap));
- ГО слота ≤ 50% капитала, СУММАРНОЕ ГО портфеля ≤ 70% (14 000₽) — «зажим со всех щелей»;
- greedy-отбор: стратегия добавляется только если calmar ПОРТФЕЛЯ растёт и бюджет ГО не превышен.

Идеология Апостола (фиксировать при любых доработках):
комбайн — готовый каркас; совершенствуется только «технология изготовления стратегий»
(зоопарк, ML-фильтр, отбор). Каркас (данные → бэктест → гейты → пул → forward) не ломать.

### 9.8 Слой движков поиска стратегий (engines/) — 2026-09-05

Идеология: каркас комбайна не меняется, наращивается СЛОЙ МОЗГОВ — разные
механизмы поиска стратегий. Все движки ссыпают кандидатов в общий приёмник
`state/engine_candidates.json`, который `tools/select_stable_pool.py` оценивает
РЕАЛЬНЫМ `run_backtest` через те же гейты (маржа, dd, ≥60% приб. месяцев,
calmar≥1.5, планка медианы месяца ≥3000₽).

Движки:
- **E1 zoo/autopilot** (`code/strategy_architect_autopilot.py`) — готовые семейства × сетка параметров.
- **E2 genetic** (`engines/genetic_engine.py` + `engines/genome.py`) — эволюционный поиск
  НОВЫХ стратегий из DSL-атомов (rsi, adx, brk, macd, cci, bb, vol, trend...).
  Геном = {"long":[атома...], "short":[...]}, сериализуем в JSON, восстанавливается
  как функция и регистрируется в `futures_lab.STRATEGY_FUNCS` под именем `ge_<hash10>`.
  Fitness = calmar + 2×доля прибыльных месяцев (гладкость важнее пика).
  Быстрый векторизованный симулятор повторяет модель исполнения run_backtest
  (вход по open след. бара, ATR stop 2.0 / take 3.0, max_hold 48, комиссия 5₽).
  Финалисты (до 5 на тикер) перепроверяются честным run_backtest в воронке.
- **E3 momentum** (`engines/momentum_engine.py`) — дневные автокорреляционные
  паттерны ret(t-lag)→ret(t), устойчивость знака на обеих половинах года.
- **E4 neural** (`engines/neural_engine.py`, v3) — нейросеть как генератор
  сигналов. Отдельная модель (ансамбль из 3 MLP) на КАЖДЫЙ тикер, обучается
  на максимально длинной истории (1095d где есть). Признаки (fv3, 38):
  импульсы/вола/RSI/BB/EMA/MACD/гэпы/серии/час + объёмы (vwap/OBV/amihud) +
  дневной контекст (завершённые дни, shift(1)) + кросс-рынок IMOEX как режим
  (merge_asof backward) + vol_regime + позиция в 10д канале + календарь.
  Разметка = честный гипотетический PnL входа по нашей экономике (вариации
  стоп/тейк/горизонт), внутри бара сначала стоп → классы short/flat/long.
  Практики ML: purge границ train/val (Lopez de Prado), random search
  гиперпараметров, macro-F1 + logloss вместо accuracy, калибровка температурой,
  веса сэмплов по силе метки, LayerNorm + grad-clip + cosine LR, ансамбль.
  Веса в `state/neural_models/<name>.pt`; `engines/register.py` регистрирует
  `nn_<hash>` в STRATEGY_FUNCS — инференс БЕЗ дообучения на лету.
- **E5+** — новый движок = новый файл `engines/<name>_engine.py` с записью в
  `engine_candidates.json`. Воронка отбора НЕ меняется.

ОБЯЗАТЕЛЬНОЕ ПРАВИЛО ДЛЯ ВСЕХ ДВИЖКОВ: после каждого прогона — честный
бэктест результата и сравнение с предыдущим лучшим («что было → что стало»),
запись в историю (`state/nn_leaderboard.json`, `engine_candidates.json`).
Улучшение принимается только если стало лучше на честном (невидимом) окне.
Holdout 60 дней не видит НИ ОДИН движок — его проверяет `tools/forward_test.py`.

**АРБИТР ВХОДОВ** (`tools/entry_arbiter.py`) — надстройка над стратегией, не замена.
Сделка стратегии остаётся решением стратегии; арбитр лишь подтверждает/ветирует её,
видя поток всех мнений (рыночные признаки + вероятности нейросети E4 + старый
ridge-метафильтр как признак). ЖЁСТКАЯ ЗАЩИТА: вариант арбитра (off/nn_veto/
arbiter) включается ТОЛЬКО если на временном val-разрезе он СТРОГО лучше «off»
и режет ≤70% сделок; иначе enabled=false и сделки идут как есть. Арбитр
не может сделать хуже по конструкции. Артефакт: `state/entry_arbiter.json`,
проверка на невидимых 60 днях — колонка arb= в `tools/forward_test.py`.

Ежедневный конвейер (`scripts/canonical_daily_research.sh`) теперь:
автопилот (E1) → генетик (E2) → моментум (E3) → нейронка (E4) → мета-кэш →
реранк → stable pool.
