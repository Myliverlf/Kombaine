# AGENTS.md — правила для агентов в этом проекте

Начни с чтения:
- `README.md` — что это и зачем;
- `ARCHITECTURE.md` — общая архитектура;
- `START.md` — карта модулей и порядок запуска.

## Архитектурные границы

- **Каркас комбайна не ломать**: конвейер «данные → бэктест → гейты → пул → forward»
  — стабильная основа. Совершенствовать можно «слой мозгов»: движки поиска
  (`engines/`) и правила генерации.
- **Риск-код детерминированный**: лимиты, гейты отбора и kill-switch не должны
  зависеть от генеративных моделей. Гейты отбора (`tools/select_stable_pool.py`)
  не ослаблять.
- Новый движок = новый файл `engines/<name>_engine.py`; воронка отбора не меняется.

## Безопасность

- Режим проекта — **paper only**. Брокерские live-вызовы запрещены; любые изменения
  режима исполнения — только с явного разрешения владельца.
- Секреты (токены, ключи) — только через переменные окружения. Никогда не добавляй
  секреты в код, конфиги, логи или коммиты.
- В репозитории не должно быть приватных данных: снапшотов аккаунтов, реальных
  сумм, путей к внутренней инфраструктуре.

## Тесты и проверка

- Запускай smallest-проверки для затронутой области перед изменениями.
- После каждого прогона движка — обязательный честный бэктест результата и сравнение
  с предыдущим лучшим («что было → что стало»); улучшение принимается только на
  невидимом (holdout) окне.
- Новый функционал сопровождается тестами и dry-run проверками.

## Стиль

- Следуй существующим конвенциям кодовой базы: модульные границы, контракты,
  именование.
- Без необоснованных новых зависимостей; предпочитай стандартную библиотеку и
  существующие модули.
- Комментарии — по делу; лишних пояснений не добавляй.
- Изменения минимальны и обратно совместимы.

## Definition of done

1. Задача решена в заявленной области.
2. Проверки пройдены (тесты/lint для затронутого кода) или причина пропуска указана.
3. Документация актуализирована (README/ARCHITECTURE, если затронута).
4. Секретов и приватных данных в изменениях нет.
